# Project Documentation

This document explains the portfolio application as it is currently implemented: its runtime, frontend sections, backend components, data model, routes, admin workflows, configuration, and deployment.

## 1. What the application does

This is a full-stack personal portfolio:

- The public site is static HTML, CSS, and browser JavaScript.
- An Express server serves the site and a JSON API.
- MongoDB stores projects, experience, contact messages, profile asset URLs, and admin sessions.
- An admin dashboard lets the portfolio owner manage projects, experience, contact messages, and uploaded files.
- Cloudinary stores profile photos, resumes, and Android APK files.

The public browser and the server communicate through same-origin HTTP requests. The public site does not need its own frontend build step.

## 3. Application startup and request flow

### Local startup

1. `dotenv.config()` loads local environment values.
2. The Express application is created and configured with proxy handling for production deployments, CORS, JSON request parsing, and sessions.
3. A connection middleware calls `ensureStoreConnected()` before allowing a request to continue. The connection promise is reused, so concurrent requests do not create duplicate connections. A failed connection clears that promise so a later request can retry.
4. The session middleware stores session records in MongoDB using `connect-mongo`.
5. Express serves `public/` as static files, exposes the admin stylesheet through `/admin-assets/admin.css`, and mounts public and admin routers.
6. Outside Vercel, `startServer()` connects to MongoDB and listens on `PORT` (5000 by default).

### Public page data flow

```text
Browser loads /index.html
  └── /js/main.js
      ├── GET /api/projects ───────> store.getProjects() ──> MongoDB
      ├── GET /api/experience ────> store.getExperience() ─> MongoDB
      ├── GET /api/profile-assets > store.getProfileAssets() > MongoDB
      └── POST /api/contact ──────> validate payload ──────> store.addContact()
```

The project, experience, and profile-asset GET endpoints are public and supply the content placeholders in the static page. A valid contact submission is stored for the admin inbox.

### Admin data flow

```text
Browser loads /admin/login
  └── POST /admin/login ──> compare username and bcrypt hash
                             └── set session.isAdmin

Browser loads /admin
  └── requireAuth ──> send admin-dashboard.html only for an admin session

Dashboard API request
  └── requireAuth ──> admin route ──> store operation ──> MongoDB
```

The `requireAuth` middleware redirects an unauthenticated page request to the login page and returns HTTP 401 JSON for an unauthenticated API request.

## 4. Public portfolio page

### `public/index.html`

The page uses semantic HTML sections, and anchors in the navigation point to each section:

- **Header/navigation:** The brand and links to About, Skills, Projects, Experience, and Contact. On narrow screens the navigation links are collapsed and controlled by `#navToggle`.
- **Hero:** Name, role statement, call-to-action links, and a decorative terminal-style profile summary. Its text is static page content.
- **About:** Biography text and the `#profilePhoto` placeholder. The public script replaces the placeholder with the uploaded photo when an asset URL is available.
- **Skills:** Static skill categories and labels; these are edited directly in the HTML, not through the admin dashboard.
- **Projects:** `#projectGrid` is a loading placeholder that `main.js` fills with project cards from the API.
- **Experience:** `#timeline` is similarly populated from the experience API.
- **Contact:** A WhatsApp link, email/social/resume links, and the contact form. The resume link remains hidden until a resume URL is returned.
- **Floating WhatsApp link and footer:** Persistent contact shortcut and a back-to-top link.
- **Script include:** Loads `/js/main.js` after the page markup so the script can find the elements it controls.

The site's personal biography, skills, displayed contact links, and hero text are authored in this HTML. Project and experience records, profile photo, and resume URL are managed through the dashboard.

### `public/js/main.js`

The browser script has these functional blocks:

1. **Mobile navigation:** Toggles the `open` class on the navigation list when the menu button is clicked and closes the menu after a link is selected.
2. **Scroll reveal:** Uses `IntersectionObserver` to add the `in` class as elements with `.reveal` enter the viewport. If the browser does not support the observer, all reveal elements are shown immediately.
3. **Project loading:** Requests `/api/projects`, checks the HTTP response, then builds project cards with project name, description, tags, and any live, source, or APK links. On failure it renders a refresh message instead of leaving the loading placeholder.
4. **Experience loading:** Requests `/api/experience` and renders timeline entries. It also provides an error state if the request fails.
5. **Profile asset loading:** Requests `/api/profile-assets`. A returned photo URL becomes an image inside the avatar; a returned resume URL unhides and safely targets the resume link in a new tab. If this request fails, the existing placeholders are retained.
6. **HTML escaping helpers:** `escapeHtml()` inserts strings as text and returns encoded HTML; `escapeAttribute()` additionally encodes quotation marks for an HTML attribute. These helpers are used for dynamic project content.
7. **Contact form submission:** Prevents a full-page submit, trims the name/email/message, disables the button while sending JSON to `/api/contact`, displays server validation messages beside the matching fields, and reports success or request failure. The button is restored in `finally`, and a successful submission resets the form.
8. **Initial loading:** Calls the three data-loading functions once the script runs.

### `public/css/style.css`

The shared public stylesheet is grouped by visual component:

- **`:root` and reset:** Theme colors, typography, radius, universal box-sizing, base body colors and spacing.
- **Background effects:** Fixed grid, glow, and top accent layers sit behind the page and do not intercept pointer events.
- **Navigation:** Sticky header, brand and links, focus-visible outlines, and a mobile menu breakpoint at 720px.
- **Hero and terminal:** Responsive headline sizing, button styles, terminal panel, and entry/blinking-cursor animations.
- **Section shell and reveal:** Common section spacing and border, heading styles, and hidden/revealed transition states.
- **About and skills:** Responsive profile layout, avatar/image treatment, biography text, skill group grid, and skill pills.
- **Projects:** Responsive project-card grid, card/title/body/tags/links, hover states, and loading/error text styling.
- **Experience:** Timeline rail, markers, dates, roles, organizations, and descriptions.
- **Contact:** Two-column contact panel, WhatsApp cards, social links, form fields, validation errors, and submission state.
- **Footer and responsive/motion rules:** Footer styling, mobile layout adjustments, and reduced-motion handling through `prefers-reduced-motion`.

The admin page imports this stylesheet too, so it reuses shared theme variables, fonts, and buttons.

## 5. Admin pages and workflows

### `views/admin-login.html`

The login document contains a username field, password field, submit button, and live status region. Its inline JavaScript:

1. Handles the form submit without a browser page reload.
2. Trims the username but leaves the password unchanged.
3. Sends both values as JSON to `POST /admin/login`.
4. Redirects to `/admin` when the response indicates success.
5. Displays the server's error message or a network failure message in the status region.

The page includes `noindex, nofollow`; this is a search-engine hint, not an access-control measure. Access control is performed by server middleware.

### `views/admin-dashboard.html`

The dashboard file contains both the admin interface markup and its controller script.

#### Page structure

- **Header:** Dashboard title, a link to the public site, and the logout button.
- **Tabs:** Projects, Contact inbox, Experience, APK uploads, and Uploads. Each tab controls a corresponding panel and the contact tab has an unread badge.
- **Overview cards:** Displays project count, experience count, and unread contact count.
- **Projects panel and dialog:** Lists projects and opens a dialog for adding or editing a project's name, description, tags, and URLs.
- **Contact inbox panel:** Lists submissions in newest-first order and supports reading, marking read/unread, marking handled/reopening, refreshing, and deletion.
- **APK upload panel:** Selects a project and APK file; the dashboard obtains a signed Cloudinary upload request and attaches the resulting URL to that project.
- **Experience panel and dialog:** Lists experience and provides a form to add an entry. Existing entries can be deleted.
- **Profile upload panel:** Uploads an image or PDF to update the public photo or resume link.

#### Dashboard JavaScript blocks

1. **Tab controller:** `activateTab()` updates `aria-selected`, keyboard tab order, panel visibility, and the URL hash. Left/right arrows, Home, and End navigate between tabs. The hash allows direct opening of a dashboard panel.
2. **Logout:** Sends `POST /admin/logout` and redirects to the login page.
3. **Escaping and API helper:** `escapeHtml()` safely places returned text into generated markup. `api()` sends requests, redirects to login on HTTP 401, throws an error for other failed requests, and treats HTTP 204 as an empty result.
4. **Project listing and editing:** `loadProjects()` fetches the public project list, updates the count and APK project selector, and renders project rows. The edit action fills the dialog form. The submit handler chooses POST for a new project and PUT for an edit; tags are split on commas. Delete uses a confirmation prompt and DELETE request. `resetProjectForm()` clears state and closes the dialog.
5. **Experience management:** `loadExperience()` renders entries and attaches delete actions. The add dialog collects dates, role, organization, and description; submit sends POST and refreshes the list. There is no edit form for experience entries in the current dashboard.
6. **Contact inbox:** `loadContacts()` renders messages, unread indicators, timestamps, and handling state. Opening an unread message marks it read. Button actions PATCH read/handled state or DELETE a message, then refresh the list and counters.
7. **APK upload:** Validates the selected file name and a 100 MB client-side size limit, requests a signed upload payload from the server, posts the APK directly to Cloudinary as a raw file, then sends the returned HTTPS URL to the protected project update route. Upload progress stages and errors appear beside the form.
8. **Photo/resume upload:** Sends a `FormData` file to `/api/admin/upload`. The server chooses whether to update the photo or resume based on the file extension. The dashboard shows the returned URL or an error.
9. **Initial dashboard data:** Calls `loadProjects()`, `loadContacts()`, and `loadExperience()` when the script is evaluated.

Dynamic admin rows escape data before building HTML. The API helper's 401 redirect is how an expired session returns the user to login.

### `admin/admin.css`

This file adds styles on top of the shared public stylesheet:

- **Login card:** Centers the sign-in form and styles its labels, inputs, button, and status messages.
- **Dashboard shell/header/tabs:** Sets a constrained dashboard width, header layout, tab states, and overview cards.
- **Panels and dialogs:** Styles content areas, panel headings, dialog backdrop, and action buttons.
- **Lists and inbox:** Styles project/contact/experience rows, unread messages, contact details, and destructive actions.
- **Admin forms:** Provides a two-column form grid, full-width controls, focus styling, and file input treatment.
- **Responsive rules:** Stacks dashboard rows and panels at tablet/mobile widths and changes forms and overview cards to one column on narrow screens.

## 6. Backend components

### `src/server.ts`

This is the Express composition root:

- Loads environment variables and creates the Express application.
- Parses the port and enables `trust proxy` in production or Vercel environments so secure cookies work behind a proxy.
- Checks the session secret: production startup fails without it; local development logs a warning and uses a development-only fallback.
- Installs CORS and JSON body parsing.
- Ensures MongoDB is connected before each request proceeds.
- Configures `express-session` with `connect-mongo`, an HTTP-only cookie, an eight-hour lifetime, and a configurable secure-cookie flag.
- Serves the `public/` directory, the admin stylesheet route, public API routers, authentication routes, and admin routes.
- Exposes `/health` with a simple status and process uptime.
- Starts a local HTTP server outside Vercel. On SIGINT, SIGTERM, or SIGUSR2, it closes the HTTP server and MongoDB connection, with a ten-second shutdown timeout.
- Exports the Express app for the Vercel runtime.

`ensureStoreConnected()` memoizes the database connection promise. If connection fails, it clears the cached promise and rethrows the error instead of continuing with an unconnected store.

### `src/data/store.ts`

This module isolates MongoDB persistence from route handlers:

- **Connection state:** Holds the active `Db` and `MongoClient`; collection accessors fail explicitly if the store has not connected.
- **Collection accessors:** Map application records to `projects`, `experience`, `contacts`, and `settings` collections.
- **Legacy migration:** Reads `data/db.json` when it exists. If it does not, it falls back to the project and experience arrays in `seed.ts`. Migration inserts projects and experience only if the corresponding MongoDB collection is empty. Optional profile assets are imported into settings if that collection is empty.
- **Mongo `_id` handling:** Application IDs are used as MongoDB `_id` values. `withoutMongoId()` removes MongoDB's storage field from API-facing objects.
- **Project functions:** List, create, update, and delete project records.
- **Contact functions:** List messages newest-first, create a message with an ID, timestamp, and initial read/handled flags, update those flags, and delete a message.
- **Experience functions:** List, create, update, and delete experience records.
- **Profile asset functions:** Read the single `profileAssets` settings document and upsert either `photoUrl` or `resumeUrl`.
- **IDs:** `makeId()` creates prefixed IDs using the current time and a random suffix.

The store does not write changes back to `data/db.json`; normal changes are persisted in MongoDB.

### `src/data/seed.ts`

Exports the initial `Project[]` and `ExperienceEntry[]` used only as fallback content when the optional legacy JSON file does not exist. During the migration, each array is copied into its MongoDB collection only if that collection has no documents yet. The sample values are placeholders intended to be replaced with actual portfolio content.

### `src/types/index.ts`

Defines the shared data shapes:

- `Project`: stable string ID, name, description, tags, optional live/source URLs, and optional APK URL.
- `ExperienceEntry`: ID, date range, role, organization, and description.
- `ProfileAssets`: optional photo and resume URLs.
- `ContactPayload`: visitor name, email, and message.
- `ContactMessage`: a contact payload plus ID, received timestamp, read state, and handled state.
- `ContactResult`: success flag and optional per-field validation messages.

These are compile-time TypeScript types; request handlers still perform runtime validation where needed.

### `src/types/session.d.ts`

Augments the `express-session` module so `SessionData` includes the optional `isAdmin` property used by login and `requireAuth`. This changes TypeScript's view of the session object, not the contents or security of the browser cookie.

### `src/middleware/auth.ts`

`requireAuth()` checks `req.session.isAdmin`. Authenticated requests continue through the route chain. Unauthenticated API requests receive a 401 JSON response; other requests are redirected to `/admin/login`.

### `src/middleware/async-handler.ts`

`asyncHandler()` wraps Express request handlers and converts rejected promises into `next(error)`. This allows Express error handling to handle asynchronous store/API errors rather than leaving rejected promises unobserved.

### `src/routes/portfolio.route.ts`

Defines three public read routes:

- `GET /api/projects` returns `{ projects: Project[] }`.
- `GET /api/experience` returns `{ experience: ExperienceEntry[] }`.
- `GET /api/profile-assets` returns `{ profileAssets: ProfileAssets }`.

Each route delegates persistence to `store.ts` and uses `asyncHandler()`.

### `src/routes/contact.route.ts`

Defines `POST /api/contact`:

1. Reads name, email, and message from the JSON body, defaulting non-string values to empty strings and trimming whitespace.
2. Validates name length (at least two characters), email format, and message length (at least ten characters).
3. Returns HTTP 400 with a `ContactResult` containing field errors when invalid.
4. Stores a valid submission through `store.addContact()` and returns `{ success: true }`.

The initial read and handled status for a new contact is set by the store layer.

### `src/routes/auth.route.ts`

- `GET /admin/login` serves the login HTML.
- `POST /admin/login` checks that the configured username and password hash exist, compares the submitted username, then uses `bcrypt.compare()` to check the password. Successful verification sets `req.session.isAdmin` and returns success; missing server configuration returns HTTP 500 and invalid credentials return HTTP 401.
- `POST /admin/logout` destroys the current session and returns success.

`ADMIN_PASSWORD_HASH` is a bcrypt hash, not the plaintext password.

### `src/routes/admin.route.ts`

This router handles the protected admin surface:

- **Dashboard page:** `GET /admin` uses `requireAuth` before serving the dashboard.
- **Cloudinary configuration:** Upload routes check the Cloudinary environment variables and return HTTP 503 if they are missing.
- **Profile image/resume upload:** Multer stores a file in memory, accepts PNG/JPG/JPEG/WEBP/PDF extensions, and limits the file to 4 MB. The file is sent to Cloudinary; the resulting secure URL is saved as `photoUrl` or `resumeUrl`.
- **APK signing endpoint:** `POST /api/admin/apk-upload-signature` signs the upload parameters server-side and returns the Cloudinary cloud name, public API key, timestamp, folder, public ID, and signature. The API secret is never returned.
- **Project endpoints:** POST creates a project; PUT updates one; DELETE removes one. Creation requires name and description. APK URLs, when supplied, must be valid HTTPS URLs.
- **Contact endpoints:** GET lists the inbox; PATCH updates boolean read/handled flags and requires at least one valid flag; DELETE removes a message.
- **Experience endpoints:** POST creates an entry and requires date range, role, organization, and description; PUT updates an entry; DELETE removes it.
- **HTTPS URL validation:** `isHttpsUrl()` rejects non-string and malformed values and accepts only parsed URLs using the HTTPS protocol.

All mutation and inbox routes use `requireAuth`. Project, experience, and profile asset GET routes remain public in `portfolio.route.ts`.

## 7. Data model and persistence

| MongoDB collection | Stored data | Application key |
|---|---|---|
| `projects` | Project content and optional APK URL | `id` / `_id` |
| `experience` | Work history entries | `id` / `_id` |
| `contacts` | Contact form submissions and inbox flags | `id` / `_id` |
| `settings` | Profile photo and resume URLs | `_id: "profileAssets"` |
| `sessions` | Express login sessions, managed by `connect-mongo` | Managed by session store |

`MONGODB_URI` selects the connection URI. `MONGODB_DB` can override the database name. If no URI is supplied, the application defaults to `mongodb://127.0.0.1:27017/portfolio`.

`data/db.json` is a legacy import source, not the live database. `.gitignore` excludes it. Existing JSON data is imported when MongoDB collections are empty; subsequent dashboard changes go to MongoDB.

## 9. Configuration and local development

### Requirements

- Node.js and npm.
- MongoDB locally or a MongoDB-compatible URI.
- Cloudinary credentials for photo/resume and APK uploads.

### Setup

1. Install dependencies with `npm install`.
2. Copy `.env.example` to `.env`.
3. Set `MONGODB_URI`, `ADMIN_USERNAME`, and a strong `SESSION_SECRET`.
4. Generate the bcrypt password hash:

   ```bash
   npm run hash-password -- yourChosenPassword
   ```

   Put the resulting `ADMIN_PASSWORD_HASH` in `.env`.
5. Set the Cloudinary cloud name, API key, and API secret if uploads are required.
6. Run the server:

   ```bash
   npm run dev
   ```

The local server defaults to `http://localhost:5000`.

### Environment variables

| Variable | Purpose |
|---|---|
| `PORT` | Local HTTP port; defaults to 5000 |
| `MONGODB_URI` | MongoDB connection URI |
| `MONGODB_DB` | Optional database-name override |
| `ADMIN_USERNAME` | Admin login name |
| `ADMIN_PASSWORD_HASH` | Bcrypt hash checked during login |
| `SESSION_SECRET` | Secret used to sign session cookies |
| `SESSION_SECURE_COOKIE` | Set to `true` when the site uses HTTPS |
| `CLOUDINARY_CLOUD_NAME` | Cloudinary cloud identifier |
| `CLOUDINARY_API_KEY` | Cloudinary API key |
| `CLOUDINARY_API_SECRET` | Cloudinary API secret; server-side only |
| `NODE_ENV` | Enables production behavior when set to `production` |
| `VERCEL` | Set by the Vercel runtime; prevents the app from opening its own listener |

Do not commit `.env`; it is excluded by `.gitignore`. In production, the server refuses to start without `SESSION_SECRET`.

## 10. Build, run, and deployment

### Package scripts

| Command | Behavior |
|---|---|
| `npm run dev` | Runs `src/server.ts` through `ts-node` and restarts on source changes using nodemon |
| `npm run build` | Compiles TypeScript from `src/` into `dist/` |
| `npm start` | Runs the compiled `dist/server.js` |
| `npm run typecheck` | Runs the TypeScript compiler without emitting output |
| `npm run hash-password -- <password>` | Prints a bcrypt hash for configuring the admin account |

`tsconfig.json` uses strict type checking, targets ES2020, uses Node16 module resolution, sets `src/` as the source root, and writes compiled files to `dist/`.

### Vercel

`vercel.json` ensures that the public files, view templates, and admin stylesheet are included with the server function. In Vercel, the app exports its Express instance instead of calling `listen()`. Configure MongoDB, admin, session, and Cloudinary values as deployment environment variables. Use HTTPS and set `SESSION_SECURE_COOKIE=true` in production.

The serverless runtime still depends on the external MongoDB and Cloudinary services for persistent data and uploads. The local `public/uploads/` folder is not used as the Cloudinary upload destination.

## 11. Security and operational behavior

- Admin pages and mutations rely on a MongoDB-backed session and `requireAuth`.
- Session cookies are HTTP-only and expire after eight hours. Secure cookies are controlled by `SESSION_SECURE_COOKIE`.
- Passwords are checked against a bcrypt hash; plaintext passwords should only be supplied to the hash script or login form.
- The Cloudinary API secret remains on the server. APK uploads use a short-lived signed parameter set generated by the server.
- Project and experience descriptions, contact contents, and project names are untrusted content when rendered in the browser; the frontend uses HTML escaping helpers before inserting generated markup.
- The server performs required-field checks for project/experience creation, contact field validation, HTTPS validation for APK URLs, and type checks for inbox state changes.
- Photo/resume upload size and extension checks are performed by Multer. APK extension and size checks are performed in the dashboard before the browser uploads directly to Cloudinary.
- A production deployment must use a strong `SESSION_SECRET`, correct Cloudinary credentials, MongoDB access controls, and HTTPS.

## 12. Maintenance notes

- To change static portfolio biography, skills, social links, or hero content, edit `public/index.html`.
- To change colors, layout, responsive rules, or public-page visuals, edit `public/css/style.css`.
- To change admin-only layout and styling, edit `admin/admin.css`.
- To change public client interactions, edit `public/js/main.js`.
- To change admin client behavior or dashboard markup, edit `views/admin-dashboard.html`.
- To change server endpoints, edit the corresponding file in `src/routes/`.
- To change persistence or migration behavior, edit `src/data/store.ts`.
- To change the initial fallback content, edit `src/data/seed.ts`.
- To change API/domain data shapes, update `src/types/index.ts` and the runtime validation that uses those fields.
- After backend TypeScript changes, run `npm run typecheck` or `npm run build`.
